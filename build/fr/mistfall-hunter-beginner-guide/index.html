Pendant la partie : observer, s'engager, se replier

Pour chaque contact, observez la salle, la route de retour et la ressource que vous devrez depenser. Engagez-vous seulement si l objectif paie le risque et si la sortie reste lisible. Faites un repli lorsqu un cooldown manque, que la formation se brise ou que la sortie change. C est un modele pratique pour gerer l incertitude, pas une regle cachee du developpeur.

Une premiere touche reussie n est pas une permission de continuer. Apres l echange, demandez-vous a quoi ressembleront les dix prochaines secondes. Si la reponse est floue, revenez vers un angle sur ou la sortie.

Solo ou cooperatif pour debuter ?

Le solo donne un retour propre : chaque choix vient de votre plan, mais il n y a aucune couche de secours. C est utile pour apprendre une route lentement avec un petit butin. Le cooperatif devient utile quand le groupe repartit les taches au lieu de simplement courir ensemble.

Les descriptions publiques confirment le solo et les escouades de trois, mais ne garantissent pas toutes les combinaisons de plateformes ou les regles regionales dans le temps. Utilisez des appels courts : contact, tiens, repli, extraction.

Erreurs de debutant et plan de recuperation

Les premiers echecs sont souvent des erreurs de processus : changer toute la build apres une mort, suivre un coequipier sans sortie, depenser toutes les ressources avant l objectif ou confondre un gros nombre avec une lecon. Apres une mort, ecrivez ce que vous saviez, ce que vous supposiez et ce que vous testerez.

Si vous n avez pas vu la menace, testez l information. Si vous n aviez aucune sortie, testez la distance. Si tout le groupe connaissait le risque, testez une regle de communication. Gardez la partie suivante volontairement simple pour isoler le changement.
